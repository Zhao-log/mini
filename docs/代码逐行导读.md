再记住 5 个高频语法：

```python
# 1. 列表推导式：一行生成新列表（相当于 Java 的 stream().map().collect()）
names = [p.name for p in products]

    ...

# 5. try/except/finally：就是 try/catch/finally

    ...

    ...

    ...
```

## 2. 项目全景：这个 Agent 到底在做什么

一句话：

```
Agent = 大模型（大脑） + 工具（手脚） + ReAct 循环（边想边做）
```

用户输入一句话后，程序会反复做三件事，直到模型给出最终答案：

```
用户输入
   ↓
① 把「历史对话 + 可用工具」发给大模型
   ↓
② 大模型返回 JSON，告诉你要么「直接回答」，要么「调用某个工具」
   ↓
③ 如果要调工具，就执行工具，把结果再发回给大模型
   ↓
回到 ①（最多循环 10 次）
```

文件分工：

| 文件 | 作用 | 生活比喻 |
| --- | --- | --- |
| `main.py` | 命令行入口，读你输入的文字 | 前台接待 |
| `src/agent.py` | 核心循环，决定「想 → 做 → 再看」 | 大脑 |
| `src/llm_client.py` | 用 HTTP 调大模型接口 | 嘴巴和耳朵 |
| `src/parser.py` | 把模型返回的文本解析成 JSON | 翻译官 |
| `src/memory.py` | 决定哪些历史消息发给模型 | 记忆整理师 |
| `src/sessions.py` | 多个独立会话，互不干扰 | 多个聊天窗口 |
| `src/tools/__init__.py` | 工具的注册、描述、执行 | 工具箱 |
| `src/tools/calculator.py` | 安全计算器 | 计算器 |
| `src/tools/search.py` | 模拟搜索 | 资料库 |
| `src/tools/todo_list.py` | 待办事项 | 记事本 |
| `src/exceptions.py` | 自定义异常 | 错误分类标签 |

先建立整体印象，再看细节。

## 3. 逐文件逐行讲解

### 3.1 exceptions.py —— 异常定义

**作用**：定义 5 个错误类型，方便上层用 `except` 精确捕获。

```python
"""自定义异常."""                      # 文件说明（文档字符串），不是可执行代码


class AgentError(Exception):            # 自定义异常基类，继承 Python 内置的 Exception
    """Agent 运行时通用错误."""          # 说明这个类代表什么错误


class ToolNotFoundError(AgentError):    # 继承 AgentError：调用了一个不存在的工具
    """工具不存在."""


class ToolExecutionError(AgentError):   # 工具存在，但执行过程中出错
    """工具执行失败."""


class LLMParseError(AgentError):        # 模型返回的内容解析失败（本文件定义了，但核心流程里主要用兜底而不是抛它）
    """LLM 输出解析失败."""


class SessionNotFoundError(AgentError): # 想操作的 session 不存在
    """Session 不存在."""
```

**要理解的点**

1. `Exception` 是 Python 所有「可捕获异常」的基类，相当于 Java 的 `Exception`。
2. 子类继承父类后，`except AgentError` 可以一次性捕获下面所有子类，和 Java 一样。
3. 这些类没有写 `pass`，因为类体里有一行文档字符串，语法上是合法的；如果类体完全为空，才需要写 `pass`。

### 3.2 sessions.py —— 会话隔离

**作用**：管理多个互不干扰的对话窗口。每个 session 有自己的消息列表 `messages` 和执行日志 `trace`。

#### 文件头与导入

```python
"""
Session & SessionManager — 多窗口隔离的对话状态管理.
...（这段是设计说明，解释为什么这么设计）
"""

from __future__ import annotations   # 让类型注解延迟求值，允许在旧版本 Python 里写 list[str] / str | None

import logging                       # Python 标准日志库，相当于 Java 的 Logger
import time                          # 时间工具，这里用来记录创建/更新时间戳
from dataclasses import dataclass, field  # dataclass：自动生成构造函数等；field：给字段设置默认值工厂
from datetime import datetime        # 把时间戳格式化成年月日时分秒
from typing import Any               # Any 表示「任意类型」，类似 Java 的 Object

logger = logging.getLogger(__name__) # 创建一个以当前模块名命名的 logger，日志里能看到来源
```

#### Session 数据类

```python
@dataclass                           # 装饰器：自动生成 __init__、__repr__、__eq__
class Session:
    """单个 session 的状态."""
    session_id: str                                              # 会话名，比如 "default"
    messages: list[dict[str, Any]] = field(default_factory=list) # 消息列表，默认新建空列表
    trace: list[str] = field(default_factory=list)               # 执行日志，默认空列表
    created_at: float = field(default_factory=time.time)         # 创建时间戳（秒）
    updated_at: float = field(default_factory=time.time)         # 最后更新时间戳

    @property                        # 把方法伪装成属性，用 s.created_at_str 而不是 s.created_at_str()
    def created_at_str(self) -> str:
        return datetime.fromtimestamp(self.created_at).strftime("%Y-%m-%d %H:%M:%S")

    @property
    def updated_at_str(self) -> str:
        return datetime.fromtimestamp(self.updated_at).strftime("%Y-%m-%d %H:%M:%S")
```

**为什么用 `field(default_factory=list)`？**
不能写 `messages: list = []`。因为 Python 的默认参数/类属性只创建一次，所有 Session 会共用同一个列表（经典坑）。`default_factory=list` 表示「每次创建对象时调用 `list()` 生成新列表」。

#### 状态管理方法

```python
    def add_message(self, msg: dict[str, Any]) -> None:   # 添加一条消息
        self.messages.append(msg)                         # 追加到列表
        self.updated_at = time.time()                     # 更新时间
        logger.debug("📥 [%s] +message: role=%s", self.session_id, msg.get("role"))
        # %s 是日志占位符，类似 Java 的 {}；msg.get("role") 取不到返回 None

    def add_trace(self, entry: str) -> None:              # 添加一条执行日志
        self.trace.append(entry)
        self.updated_at = time.time()
        logger.debug("📝 [%s] +trace: %s", self.session_id, entry[:80])  # 只打印前 80 个字符

    def get_messages(self) -> list[dict[str, Any]]:
        return list(self.messages)     # 复制一份再返回，防止外部直接改内部列表（防御性拷贝）

    def get_trace_text(self) -> str:
        return "\n".join(self.trace)   # 把日志列表用换行拼成一个字符串

    def message_count(self) -> int:
        return len(self.messages)      # len() 取长度，类似 list.size()

    def user_assistant_turns(self) -> int:
        """统计有多少轮 user+assistant 对（粗略）."""
        count = 0
        for msg in self.messages:                                   # for-each 循环
            if msg.get("role") == "assistant" and msg.get("content"):  # 是 assistant 且有内容
                count += 1
        return count

    def reset(self) -> None:
        """清空对话历史但保留 trace."""
        self.messages.clear()          # 清空列表
        self.updated_at = time.time()
        self.add_trace("🔄 Session 已重置")
```

#### SessionManager 注册中心

```python
class SessionManager:
    """Session 注册中心."""

    def __init__(self):                                  # 构造函数
        self._sessions: dict[str, Session] = {}          # 私有字典：session_id → Session
        # 约定：以下划线开头的变量表示「内部使用」，但 Python 不会强制禁止访问

    def get_or_create(self, session_id: str) -> Session:
        if session_id not in self._sessions:             # 不存在
            logger.info("🆕 创建新 session: %s", session_id)
            self._sessions[session_id] = Session(session_id=session_id)  # 新建并放入字典
        return self._sessions[session_id]                # 返回已有的或刚建的

    def get(self, session_id: str) -> Session | None:    # 查，找不到返回 None
        return self._sessions.get(session_id)            # dict.get 不会因为 key 不存在而抛异常

    def exists(self, session_id: str) -> bool:
        return session_id in self._sessions              # in 判断 key 是否存在

    def delete(self, session_id: str) -> bool:
        if session_id in self._sessions:
            del self._sessions[session_id]               # 删除这个 key
            logger.info("🗑️ 删除 session: %s", session_id)
            return True
        return False

    def list_sessions(self) -> list[str]:
        return sorted(self._sessions.keys())             # 取所有 key 并排序

    def session_info(self) -> list[dict[str, Any]]:
        """返回每个 session 的概览信息（CLI 展示用）."""
        return [
            {
                "id": s.session_id,
                "messages": s.message_count(),
                "turns": s.user_assistant_turns(),
                "created": s.created_at_str,
                "updated": s.updated_at_str,
            }
            for s in self._sessions.values()             # 列表推导式：对每个 Session 生成一个字典
        ]
```

**这一节的核心**

- 一个 `Session` = 一个聊天窗口；`SessionManager` = 窗口管理器。
- 所有数据都在内存里，程序退出就没了（题目要求本来就允许简单实现）。
- 不同 `session_id` 的消息完全隔离，这就是「多窗口互不影响」的实现方式。

### 3.3 parser.py —— 解析模型输出

**作用**：大模型返回的是一段**文本**（理想情况下是 JSON），但这个文本可能带 Markdown 代码块、前后废话、甚至不是 JSON。这个文件负责尽力把它变成程序能用的结构化对象。

#### 文件头：4 层容错策略

```python
"""
Parser — 从 LLM 输出文本中提取结构化 JSON 并解析。

容错策略（按优先级降级）:
  1. 直接 json.loads
  2. 从 ```json ... ``` 代码块里提取再解析
  3. 从 { ... } 大括号里提取最可能的 JSON 片段
  4. 全部失败 → 把整个输出当 final_answer（兜底）
"""

from __future__ import annotations   # 延迟类型注解

import json                          # 解析 JSON 的标准库
import logging
import re                            # 正则表达式，用来找 ```json ... ``` 代码块
from dataclasses import dataclass
from typing import Any, Literal       # Literal 表示「只能是这几个字面值之一」

logger = logging.getLogger(__name__)
```

#### ParsedResponse：解析后的统一结构

```python
@dataclass
class ParsedResponse:
    """LLM 输出的结构化解析结果."""
    thought: str | None                           # 思考过程，可能没有
    action: Literal["tool_call", "final_answer"]  # 只能是这两个值之一
    tool_name: str | None                         # 工具名（调用工具时才有）
    tool_args: dict[str, Any] | None              # 工具参数
    final_answer: str | None                      # 最终回答（直接回答时才有）
    raw_json: dict[str, Any] | None = None        # 原始 JSON，调试用（有默认值，所以放在后面）
    parse_method: str = ""                        # 用了哪种解析策略，调试用
```

> Python 规则：有默认值的字段必须放在没有默认值的字段后面，否则语法报错。

#### 两个提取工具函数

```python
def _extract_json_code_block(text: str) -> str | None:
    """从 ```json ... ``` 或 ``` ... ``` 中提取."""
    # 正则解释：
    # ```            三个反引号
    # (?:json)?      可选的 json 字样
    # \s*\n          空白和换行
    # (.*?)          非贪婪地捕获中间所有内容
    # \n?\s*```      结尾的三个反引号
    m = re.search(r"```(?:json)?\s*\n(.*?)\n?\s*```", text, re.DOTALL | re.IGNORECASE)
    # re.DOTALL 让 . 能匹配换行；re.IGNORECASE 忽略大小写
    if m:
        return m.group(1).strip()   # group(1) 是括号里捕获的内容，strip 去掉首尾空白
    return None                     # 没找到返回 None


def _extract_json_braces(text: str) -> str | None:
    """从文本中找到最外层 { ... } 包裹的内容."""
    start = text.find("{")          # 第一个左大括号的位置，找不到返回 -1
    end = text.rfind("}")           # 最后一个右大括号的位置
    if start != -1 and end != -1 and end > start:
        candidate = text[start:end + 1]   # 切片：包含 start，不包含 end+1
        try:
            json.loads(candidate)         # 先试解析，合法才返回
            return candidate
        except json.JSONDecodeError:      # 不是合法 JSON
            pass                          # pass = 什么也不做，继续往下走
    return None
```

#### 主函数：四步降级解析

```python
def parse_llm_response(raw_text: str) -> ParsedResponse:
    """解析 LLM 输出为 ParsedResponse."""
    text = raw_text.strip()                              # 去掉首尾空白
    logger.debug("📝 原始 LLM 输出:\n%s", text[:500])     # 只记录前 500 字，避免日志爆炸

    json_str = None                                      # 记录「成功解析出的 JSON 文本」
    method = ""                                          # 记录用了哪种策略

    # 策略 1：整段文本就是 JSON
    try:
        data = json.loads(text)                          # 解析成 Python 的 dict / list
        json_str = text
        method = "direct"
    except json.JSONDecodeError:
        pass                                             # 失败就继续尝试下一种

    # 策略 2：从 ```json ... ``` 代码块里提取
    if json_str is None:
        extracted = _extract_json_code_block(text)
        if extracted:
            try:
                data = json.loads(extracted)
                json_str = extracted
                method = "code_block"
            except json.JSONDecodeError:
                pass

    # 策略 3：从第一个 { 到最后一个 } 提取
    if json_str is None:
        extracted = _extract_json_braces(text)
        if extracted:
            try:
                data = json.loads(extracted)
                json_str = extracted
                method = "braces"
            except json.JSONDecodeError:
                pass

    # 策略 4：全部失败 → 把整段文本当成最终回答，保证程序不崩
    if json_str is None:
        logger.warning("⚠️ LLM 输出无法解析为 JSON，降级为 final_answer")
        return ParsedResponse(
            thought=None,
            action="final_answer",
            tool_name=None,
            tool_args=None,
            final_answer=text,
            raw_json=None,
            parse_method="fallback_text",
        )

    method = method or "unknown"     # 万一 method 还是空串，兜底成 unknown

    # 某些模型会输出 [{...}] 这样的单元素数组，帮他拆开
    if isinstance(data, list) and len(data) == 1:
        data = data[0]

    # 顶层必须是对象（dict），否则也降级
    if not isinstance(data, dict):
        logger.warning("⚠️ JSON 顶层不是 dict，降级为 final_answer")
        return ParsedResponse(
            thought=None,
            action="final_answer",
            tool_name=None,
            tool_args=None,
            final_answer=str(data),
            raw_json=None,
            parse_method="fallback_non_dict",
        )

    # 从 JSON 里取字段；or 的用法：左边是空字符串/None 时取右边
    thought = data.get("thought") or data.get("reasoning")   # 兼容 reasoning 字段名
    action = data.get("action", "")                          # 取不到给空串
    tool_name = data.get("tool_name")
    tool_args = data.get("tool_args")
    final_answer = data.get("answer") or data.get("final_answer")  # 兼容两种字段名

    # 校验 action；模型可能乱写
    if action not in ("tool_call", "final_answer"):
        if tool_name:
            action = "tool_call"      # 有工具名，就认为它想调工具
        else:
            action = "final_answer"   # 否则当作直接回答

    # 进一步校验工具调用
    if action == "tool_call":
        if not tool_name:
            logger.warning("⚠️ action=tool_call 但 tool_name 缺失，降级为 final_answer")
            action = "final_answer"
            final_answer = final_answer or f"(模型输出了 tool_call 但缺少工具名)\n{json.dumps(data, ensure_ascii=False)}"
            # f"..." 是格式化字符串；json.dumps 把 dict 转回 JSON 文本，ensure_ascii=False 保留中文

        if tool_args is None:
            tool_args = {}            # 没参数就当空字典
        elif isinstance(tool_args, str):
            try:
                tool_args = json.loads(tool_args)   # 参数是字符串形式的 JSON，再解析一次
            except json.JSONDecodeError:
                tool_args = {"_raw": tool_args}     # 实在解析不了，原样塞进 _raw

    if action == "final_answer" and not final_answer:
        final_answer = data.get("answer") or "(模型未给出最终答案)"

    logger.info("✅ 解析完成 [%s]: action=%s tool=%s", method, action,
                tool_name if action == "tool_call" else "-")

    return ParsedResponse(
        thought=thought,
        action=action,
        tool_name=tool_name,
        tool_args=tool_args if isinstance(tool_args, dict) else {},
        final_answer=final_answer,
        raw_json=data,
        parse_method=method,
    )
```

**这一节的核心**

- 大模型输出不可靠，所以要「一层一层退」：直接解析 → 代码块 → 大括号 → 整段当答案。
- 解析结果统一成 `ParsedResponse`，后面的 `Agent` 就不用关心模型到底怎么写的。
- `action` 只有两种：调工具 `tool_call`，或直接回答 `final_answer`。

**一个容易困惑的点**：变量 `data` 在策略 1/2/3 里赋值，但只有 `json_str is None` 的分支才会用到它。能保证用到 `data` 时它一定已经被赋值。

### 3.4 memory.py —— 上下文管理

**作用**：不是把所有历史消息都发给大模型，而是先**过滤、截断、压缩**，控制 token 成本。

#### 设计说明

```python
"""
ContextManager — 管理塞入 LLM context 的消息列表.

题目核心考点: "自行判断哪些信息要塞入 context"

设计决策:
  ✅ 塞入: 用户输入、LLM 最终回答、工具调用记录、工具结果（截断到 500 字符）
  ❌ 不塞: 思考过程（thought）、失败的工具调用细节
...
"""

from __future__ import annotations
import logging
from typing import Any

logger = logging.getLogger(__name__)
```

#### 可调参数

```python
class ContextManager:
    """构建 & 压缩 LLM context."""

    MAX_ROUNDS: int = 20              # 最多保留 20 轮 user+assistant
    MAX_CHARS: int = 16000            # 字符上限，约等于 4000 token（字符数 / 4）
    COMPRESS_THRESHOLD: int = 14000   # 预留的压缩阈值（当前版本未直接使用）
    TOOL_RESULT_MAX_LEN: int = 500    # 单条工具结果最多 500 字符
```

#### 主入口：build_context

```python
    def build_context(self, messages, system_prompt=None) -> list[dict[str, Any]]:
        """
        从原始 messages 构建要发给 LLM 的 context.
        流程: 过滤 → 轮次截断 → 估算 → 超限压缩 → 前插 system prompt
        """
        if not messages:                                   # 空列表
            return [{"role": "system", "content": system_prompt}] if system_prompt else []
            # 三元表达式：有 system_prompt 就返回一条 system 消息，否则返回空列表

        filtered = self._filter_messages(messages)          # 第 1 步：过滤字段
        logger.info("📋 过滤后: %d 条消息", len(filtered))

        truncated = self._truncate_by_rounds(filtered)      # 第 2 步：按轮次截断
        if len(truncated) != len(filtered):
            logger.info("✂️ 轮次截断: %d → %d 条", len(filtered), len(truncated))

        total_chars = self._estimate_chars(truncated)       # 第 3 步：估算字符数
        logger.info("📏 估算字符数: %d（≈ %d tokens）", total_chars, total_chars // 4)
        # // 是整除，类似 Java 的整数除法

        if total_chars > self.MAX_CHARS:                    # 第 4 步：超限就压缩
            compressed = self._compress_early_messages(truncated)
            new_chars = self._estimate_chars(compressed)
            logger.info("🗜️ 压缩后: %d 条消息, %d 字符", len(compressed), new_chars)
            final_messages = compressed
        else:
            final_messages = truncated

        result = list(final_messages)                       # 第 5 步：复制一份
        if system_prompt:
            if result and result[0].get("role") == "system":
                # 压缩后可能已经有一条 system 摘要，把它和新的 system prompt 合并
                merged = f"{system_prompt}\n\n{result[0].get('content', '')}"
                result[0] = {"role": "system", "content": merged}
            else:
                result.insert(0, {"role": "system", "content": system_prompt})
                # insert(0, x) 插到列表最前面

        return result
```

> 为什么压缩后要把两条 system 合并？有些大模型供应商不允许出现多条 system 消息。

#### 过滤：_filter_messages

```python
    def _filter_messages(self, messages):
        """
        保留: role, content, tool_calls, tool_call_id
        移除: thought（思考过程不重复发给模型）
        截断: tool 结果（太长浪费 token）
        """
        filtered = []
        for msg in messages:
            role = msg.get("role", "")
            clean: dict[str, Any] = {"role": role}      # 新字典只放必要字段

            if role == "user":
                clean["content"] = msg.get("content", "")

            elif role == "assistant":
                clean["content"] = msg.get("content") or ""
                if msg.get("tool_calls"):
                    clean["tool_calls"] = msg["tool_calls"]   # 保留「我调过什么工具」
                # 故意不复制 thought

            elif role == "tool":
                content = msg.get("content", "")
                if len(content) > self.TOOL_RESULT_MAX_LEN:
                    content = content[:self.TOOL_RESULT_MAX_LEN] + f"\n...(截断，原始长度 {len(content)} 字符)"
                clean["content"] = content
                if msg.get("tool_call_id"):
                    clean["tool_call_id"] = msg["tool_call_id"]  # 工具结果要和调用 ID 对应

            elif role == "system":
                clean["content"] = msg.get("content", "")

            filtered.append(clean)      # 加进结果列表
        return filtered
```

#### 轮次截断：_truncate_by_rounds

```python
    def _truncate_by_rounds(self, messages):
        """保留最近 MAX_ROUNDS 轮；以 user 消息为一轮的起点，避免留下孤立消息."""
        if len(messages) <= 2:
            return messages

        user_indices = [i for i, m in enumerate(messages) if m.get("role") == "user"]
        # enumerate 同时给出下标和元素；这句收集所有 user 消息的下标

        if len(user_indices) <= self.MAX_ROUNDS:
            return messages                      # 没超过上限，不截断

        cutoff = user_indices[-self.MAX_ROUNDS]  # 倒数第 20 个 user 的下标
        return messages[cutoff:]                 # 从它开始一直取到结尾
```

#### 估算字符数：_estimate_chars

```python
    @staticmethod                                  # 静态方法，不需要 self
    def _estimate_chars(messages) -> int:
        """粗略估算 context 总字符数."""
        total = 0
        for msg in messages:
            total += len(msg.get("role", "")) + 4   # role + 固定格式开销
            total += len(msg.get("content", ""))
            if msg.get("tool_calls"):
                import json                         # 局部导入（不推荐但在函数里合法）
                total += len(json.dumps(msg["tool_calls"], ensure_ascii=False))
            if msg.get("tool_call_id"):
                total += len(msg["tool_call_id"])
        return total
```

> 严格来说应该把 `import json` 放到文件顶部，这里写在函数里只是风格问题，不影响运行。

#### 压缩：_compress_early_messages

```python
    def _compress_early_messages(self, messages):
        """
        把最早的一半对话压成一条 summary system 消息。
        不调用 LLM，只用简单规则拼接（省一次 API 费用）。
        """
        if len(messages) <= 4:
            return messages                       # 太少，不压缩

        user_indices = [i for i, m in enumerate(messages) if m.get("role") == "user"]
        if len(user_indices) <= 2:
            return messages                       # 用户轮次太少，不压缩

        half = len(user_indices) // 2             # 一半（整除）
        cutoff = user_indices[half]               # 从中间那个 user 消息切开

        early_messages = messages[:cutoff]        # 前半段：将被压缩
        late_messages = messages[cutoff:]         # 后半段：原样保留

        summary_lines = ["[历史对话概要（已压缩）]:"]
        i = 0
        while i < len(early_messages):            # while 循环，手动控制下标
            msg = early_messages[i]
            if msg.get("role") == "user":
                user_text = msg.get("content", "")[:100]   # 只取前 100 字
                ans_text = ""
                for j in range(i + 1, min(i + 8, len(early_messages))):
                    # 向下最多找 7 条，看有没有 assistant 的回答
                    if early_messages[j].get("role") == "assistant" and early_messages[j].get("content"):
                        ans_text = early_messages[j]["content"][:100]
                        break
                summary_lines.append(f"  - 用户问: {user_text}")
                if ans_text:
                    summary_lines.append(f"    → 回答: {ans_text}")
                i += 1
            else:
                i += 1

        summary = "\n".join(summary_lines)         # 拼成一段文本
        result = [{"role": "system", "content": summary}]   # 摘要作为 system 消息
        result.extend(late_messages)               # extend 把另一个列表的元素逐个追加
        return result
```

**这一节的核心**

- 发给模型的上下文不是「全部历史」，而是经过清洗的最近对话。
- 工具执行结果最多保留 500 字，避免一次搜索把上下文撑爆。
- 超过 16000 字符时，把前一半对话压成一段摘要，保留后一半原文。
- `COMPRESS_THRESHOLD` 定义了但没用到，属于预留参数，不影响功能。

**作用**：不用任何大模型 SDK，直接用 `httpx` 发一个 HTTP POST 请求，调用 OpenAI 兼容的 `/chat/completions` 接口。

#### 文件头与 LLMResponse

from __future__ import annotations

#### 构造函数：从环境变量读配置

```python
class LLMClient:
    def __init__(self, base_url=None, api_key=None, model=None, timeout=60.0):
        # 优先级：参数 > 环境变量 > 默认值
        self.base_url = (base_url or os.environ.get("LLM_BASE_URL") or "https://api.openai.com/v1").rstrip("/")
        # rstrip("/") 去掉末尾斜杠，避免拼出 //chat/completions
        self.api_key = api_key or os.environ.get("LLM_API_KEY", "")
        self.model = model or os.environ.get("LLM_MODEL", "gpt-4o-mini")
        self.timeout = timeout       # HTTP 超时时间（秒）

        if not self.api_key:
            logger.warning("LLM_API_KEY 未设置，调用可能会失败。请在 .env 文件中配置。")
```

> 环境变量来自 `.env` 文件，由 `main.py` 里的 `load_dotenv()` 加载进 `os.environ`。

#### chat()：组装请求并调用

```python
    def chat(self, messages, tools=None, system_prompt=None, temperature=0.7) -> LLMResponse:
        """
        :param messages: 对话历史
        :param tools: 工具定义列表（JSON Schema）
        :param system_prompt: 系统提示词
        :param temperature: 采样温度，0 更稳定，1 更有创意
        """
        url = f"{self.base_url}/chat/completions"       # 拼出完整地址

        api_messages: list[dict[str, Any]] = []
        if system_prompt:
            api_messages.append({"role": "system", "content": system_prompt})
        api_messages.extend(self._normalize_messages(messages))   # 追加历史消息

        body: dict[str, Any] = {
            "model": self.model,
            "messages": api_messages,
            "temperature": temperature,
            "response_format": {"type": "json_object"},   # 要求模型只输出 JSON
        }

        if tools:
            body["tools"] = tools               # 把工具清单告诉模型
            body["tool_choice"] = "auto"        # 让模型自己决定用不用工具

        headers = {
            "Authorization": f"Bearer {self.api_key}",   # 鉴权：Bearer + API Key
            "Content-Type": "application/json",
        }

        logger.debug("→ POST %s | messages=%d tools=%s", url, len(api_messages), bool(tools))

        data = self._post(url, headers, body)            # 真正发请求（见下）

        choices = data.get("choices", [])                # OpenAI 格式：答案在 choices 数组里
        if not choices:
            raise RuntimeError(f"LLM 响应缺少 choices 字段: {json.dumps(data, ensure_ascii=False)[:500]}")

        message = choices[0].get("message", {}) or {}    # 取第一条
        content = self._coerce_content(message)          # 把各种格式统一成 JSON 字符串

        return LLMResponse(content=content, raw=data, usage=data.get("usage"))
```

#### _post()：HTTP 请求 + 供应商兼容降级

```python
    def _post(self, url, headers, body):
        """
        部分供应商不支持 response_format=json_object，会返回 400。
        这时去掉该字段重试一次。
        """
        try:
            with httpx.Client(timeout=self.timeout) as client:   # with 自动关闭连接
                resp = client.post(url, headers=headers, json=body)

                if resp.status_code >= 400:                       # 4xx/5xx 都算失败
                    text = resp.text
                    logger.error("LLM API error: %s\n%s", resp.status_code, text)

                    if (
                        resp.status_code == 400
                        and "response_format" in body
                        and "response_format" in text                # 错误信息提到该字段
                    ):
                        logger.warning("供应商不支持 response_format，降级去掉该字段后重试一次")
                        fallback = {k: v for k, v in body.items() if k != "response_format"}
                        # 字典推导式：复制 body，但跳过 response_format
                        resp = client.post(url, headers=headers, json=fallback)
                        if resp.status_code >= 400:
                            raise RuntimeError(f"LLM API 返回 {resp.status_code}: {resp.text}")
                        return resp.json()

                    raise RuntimeError(f"LLM API 返回 {resp.status_code}: {text}")

                return resp.json()                                # 把响应体解析成 dict

        except httpx.RequestError as e:                           # 网络错误/超时
            logger.error("LLM API 请求失败: %s", e)
            raise RuntimeError(f"LLM API 请求失败: {e}") from e
            # from e 保留原始异常链，方便排查
        except json.JSONDecodeError as e:                         # 响应不是 JSON
            logger.error("LLM 响应不是合法 JSON: %s", e)
            raise RuntimeError(f"LLM 响应不是合法 JSON: {e}") from e
```

#### _coerce_content()：把不同供应商的响应统一

```python
    @staticmethod
    def _coerce_content(message: dict[str, Any]) -> str:
        content = message.get("content")

        # 情况 1：content 是数组（多模态格式，如 [{"type":"text","text":"..."}]）
        if isinstance(content, list):
            parts = []
            for item in content:
                if isinstance(item, str):
                    parts.append(item)
                elif isinstance(item, dict) and isinstance(item.get("text"), str):
                    parts.append(item["text"])
            content = "".join(parts) or None      # 拼成一个字符串

        # 情况 2：正常文本，直接用
        if isinstance(content, str) and content.strip():
            return content

        # 情况 3：content 为空，但模型用了原生 tool_calls（function calling）
        tool_calls_raw = message.get("tool_calls") or []
        if tool_calls_raw:
            first = tool_calls_raw[0]
            fn = first.get("function", {}) if isinstance(first, dict) else {}
            raw_args = fn.get("arguments", "{}")
            if isinstance(raw_args, str):
                try:
                    parsed_args = json.loads(raw_args)   # arguments 通常是 JSON 字符串
                except json.JSONDecodeError:
                    parsed_args = {"_raw": raw_args}
            elif isinstance(raw_args, dict):
                parsed_args = raw_args
            else:
                parsed_args = {}

            # 把原生 tool_call 转成我们自己约定的 JSON 文本
            return json.dumps(
                {
                    "thought": message.get("reasoning_content") or "模型调用了工具",
                    "action": "tool_call",
                    "tool_name": fn.get("name"),
                    "tool_args": parsed_args,
                    "answer": None,
                },
                ensure_ascii=False,      # 中文不转成 \uXXXX
            )

        # 情况 4：完全空响应，也不能让程序崩
        return json.dumps(
            {
                "thought": message.get("reasoning_content") or "",
                "action": "final_answer",
                "tool_name": None,
                "tool_args": None,
                "answer": "(模型返回为空)",
            },
            ensure_ascii=False,
        )
```

#### _normalize_messages()：内部格式 → OpenAI 格式

```python
    @staticmethod
    def _normalize_messages(messages):
        normalized = []
        for msg in messages:
            role = msg.get("role", "user")

            if role == "tool":
                normalized.append({
                    "role": "tool",
                    "tool_call_id": msg.get("tool_call_id", ""),   # 必须带调用 ID
                    "content": str(msg.get("content", "")),        # 必须是字符串
                })
                continue      # 跳过本轮剩余代码，进入下一次 for 循环

            if role == "assistant":
                clean = {"role": "assistant", "content": msg.get("content") or ""}
                tool_calls = msg.get("tool_calls")
                if tool_calls:
                    clean["tool_calls"] = [LLMClient._to_openai_tool_call(tc) for tc in tool_calls]
                normalized.append(clean)
                continue

            normalized.append({"role": role, "content": str(msg.get("content", ""))})

        return normalized
```

#### _to_openai_tool_call()：工具调用格式转换

```python
    @staticmethod
    def _to_openai_tool_call(tc):
        call_id = tc.get("id") or f"call_{uuid4().hex[:12]}"   # 没有 ID 就随机生成

        fn = tc.get("function")
        if isinstance(fn, dict):                 # 已经是 OpenAI 原生格式
            name = fn.get("name", "")
            raw_args = fn.get("arguments", "{}")
        else:                                    # 我们内部的简化格式
            name = tc.get("name", "")
            raw_args = tc.get("arguments", {})

        if isinstance(raw_args, str):
            arguments = raw_args
        else:
            arguments = json.dumps(raw_args if raw_args is not None else {}, ensure_ascii=False)
        # OpenAI 要求 arguments 必须是「JSON 字符串」，不能直接传 dict

        return {
            "id": call_id,
            "type": "function",
            "function": {"name": name, "arguments": arguments},
        }
```

**这一节的核心**

- 调用大模型 = 发一个 JSON 请求，核心只有两步：拼 `messages`、解析 `choices[0].message`。
- 提示词里要求「只输出 JSON」，但不同供应商支持程度不同，所以做了降级重试。
- 模型可能用「原生 tool_calls」而不是 JSON 文本，`_coerce_content` 把两种情况统一。
- 发回给模型的历史消息必须严格符合 OpenAI 格式，`_normalize_messages` 负责清洗。

### 3.6 tools/__init__.py —— 工具注册中心

**作用**：定义「工具」长什么样（名字、描述、参数、执行函数），并统一管理、统一执行。

#### 为什么需要 session_id 注入

```python
import contextvars     # 上下文变量：可以在不传参的情况下，沿调用链共享值

# 当前正在执行的 session_id
CURRENT_SESSION_ID: contextvars.ContextVar[str | None] = contextvars.ContextVar(

```

> 待办工具需要知道「现在是哪个会话」，但不想让大模型去填 `session_id`（模型不该知道这个内部概念）。所以由代码在执行工具时临时写入 `CURRENT_SESSION_ID`，工具内部再读取。可以理解为「线程本地变量」，但它对异步也安全。

#### Tool：一个工具的完整定义

```python
@dataclass
class Tool:
    """单个工具的定义."""
    name: str                                   # 工具名，模型调用时用它
    description: str                            # 给模型看的说明，越清楚模型越会用
    parameters: dict[str, Any]                  # JSON Schema，描述参数类型
    handler: Callable[..., Any]                 # 真正执行的 Python 函数

    def to_schema(self) -> dict[str, Any]:
        """转成 OpenAI tools 列表里的一项."""
        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description,
                "parameters": self.parameters,
            },
        }

    def execute(self, **kwargs: Any) -> str:
        """执行工具，捕获异常并返回错误字符串."""
        try:
            result = self.handler(**kwargs)      # 把参数展开传给函数
            return str(result)                    # 统一转成字符串
        except TypeError as e:                    # 参数名/数量不对
            sig = inspect.signature(self.handler) # 拿到函数签名，方便报错
            raise ToolExecutionError(f"参数错误: {e}. 期望签名: {sig}") from e
        except Exception as e:                    # 其他任何错误
            raise ToolExecutionError(f"{self.name} 执行失败: {e}") from e
```

#### ToolRegistry：注册与执行

```python
class ToolRegistry:
    """工具注册中心."""

    def __init__(self):
        self._tools: dict[str, Tool] = {}       # 工具名 → Tool 对象

    def register(self, tool: Tool) -> None:
        if tool.name in self._tools:
            logger.warning("工具 '%s' 已存在，将被覆盖", tool.name)
        self._tools[tool.name] = tool           # 存进字典
        logger.info("✓ 注册工具: %s", tool.name)

    def unregister(self, name: str) -> None:
        self._tools.pop(name, None)              # 删除，不存在也不报错

    def list_tools(self) -> list[str]:
        return list(self._tools.keys())

    def get_all_tools_schema(self) -> list[dict[str, Any]]:
        """返回给 LLM 的 tools 参数列表."""
        return [t.to_schema() for t in self._tools.values()]

    def get_tools_description_text(self) -> str:
        """把工具说明拼成纯文本，供 system prompt 使用."""
        lines = []
        for t in self._tools.values():
            params_desc = ""
            props = t.parameters.get("properties", {})     # 参数定义
            required = t.parameters.get("required", [])    # 必填参数名
            for pname, pschema in props.items():
                marker = "(必填)" if pname in required else "(可选)"
                pdesc = pschema.get("description", "")
                ptype = pschema.get("type", "any")
                params_desc += f"      - {pname} {marker}: {ptype}, {pdesc}\n"
            lines.append(f"  - {t.name}: {t.description}\n    参数:\n{params_desc.rstrip()}")
        return "\n".join(lines)

    def execute(self, name: str, args: dict[str, Any], session_id: str | None = None) -> str:
        """根据名称执行工具."""
        if name not in self._tools:
            available = ", ".join(self._tools.keys()) or "(无可用工具)"
            raise ToolNotFoundError(f"工具 '{name}' 不存在。可用工具: {available}")

        tool = self._tools[name]
        logger.info("🔧 执行工具: %s(%s)", name, args)

        token = CURRENT_SESSION_ID.set(session_id)   # 写入当前会话 ID
        try:
            result = tool.execute(**args)            # 执行
        finally:
            CURRENT_SESSION_ID.reset(token)          # 无论成功失败都恢复，避免串会话
        logger.info("🔧 工具返回: %s", result[:200])
        return result
```

**这一节的核心**

- 大模型只认识「JSON Schema 描述」，真正的 Python 函数在本地执行。
- 新增一个工具只需要：写一个 handler 函数 → 用 `Tool(...)` 包一层 → `registry.register(...)`。
- `contextvars` 让工具能拿到当前会话，但不需要暴露给模型。

### 3.7 tools/calculator.py —— 安全计算器

**作用**：让模型能算数学题。难点不是「算」，而是「安全地算」——绝不能直接 `eval()` 用户/模型给的字符串。

#### 白名单设计

```python
import ast          # 把 Python 表达式解析成语法树（AST）
import math
import operator     # 提供加减乘除等函数

from . import Tool  # 从同包的 __init__.py 导入 Tool

# 只允许这些语法节点
_ALLOWED_NODES = (
    ast.Expression,  # 整个表达式
    ast.BinOp,       # 二元运算：a + b
    ast.UnaryOp,     # 一元运算：-a
    ast.Constant,    # 常量数字
    ast.Name,        # 变量名（只允许 pi、e）
    ast.Load,        # 读取变量
    ast.Call,        # 函数调用（只允许白名单函数）
)

_UNARY_OPS = {ast.UAdd: operator.pos, ast.USub: operator.neg}   # +a、-a

_BINARY_OPS = {
    ast.Add: operator.add,          # +
    ast.Sub: operator.sub,          # -
    ast.Mult: operator.mul,         # *
    ast.Div: operator.truediv,      # /
    ast.FloorDiv: operator.floordiv,# //
    ast.Mod: operator.mod,          # %
    ast.Pow: operator.pow,          # **
}

_ALLOWED_FUNCTIONS = {
    "abs": abs, "round": round, "min": min, "max": max, "sum": sum,
    "sqrt": math.sqrt, "pow": pow, "sin": math.sin, "cos": math.cos,
    "tan": math.tan, "log": math.log, "log10": math.log10,
}

_ALLOWED_VARS = {"pi": math.pi, "e": math.e}

_MAX_POW_EXPONENT = 1000     # 指数上限
_MAX_POW_BASE = 10 ** 6      # 底数上限
_MAX_DEPTH = 200             # 递归深度上限
```

> 为什么要白名单？因为 `eval("__import__('os').system('rm -rf /')")` 能执行任意代码。把表达式解析成语法树后，只允许「数字、+-*/、几个数学函数」，其他节点一律拒绝。

#### 递归求值：_safe_eval

```python
def _safe_eval(node: ast.AST, depth: int = 0) -> Any:
    """递归求值 AST 节点."""
    if depth > _MAX_DEPTH:
        raise ValueError(f"表达式嵌套过深（上限 {_MAX_DEPTH} 层）")

    if not isinstance(node, _ALLOWED_NODES):
        raise ValueError(f"不支持的语法节点: {type(node).__name__}")

    if isinstance(node, ast.Expression):
        return _safe_eval(node.body, depth + 1)      # 从根节点往下

    if isinstance(node, ast.Constant):
        value = node.value
        if isinstance(value, bool) or not isinstance(value, (int, float)):
            raise ValueError(f"不支持的常量类型: {type(value).__name__}")
        return value                                  # 只接受数字

    if isinstance(node, ast.Name):
        if node.id in _ALLOWED_VARS:
            return _ALLOWED_VARS[node.id]             # pi / e
        raise ValueError(f"不支持的变量: {node.id}")

    if isinstance(node, ast.UnaryOp):
        op_func = _UNARY_OPS.get(type(node.op))
        if not op_func:
            raise ValueError(f"不支持的一元运算符: {type(node.op).__name__}")
        return op_func(_safe_eval(node.operand, depth + 1))

    if isinstance(node, ast.BinOp):
        op_func = _BINARY_OPS.get(type(node.op))
        if not op_func:
            raise ValueError(f"不支持的二元运算符: {type(node.op).__name__}")
        left = _safe_eval(node.left, depth + 1)       # 先算左边
        right = _safe_eval(node.right, depth + 1)     # 再算右边
        if isinstance(node.op, (ast.Div, ast.FloorDiv, ast.Mod)) and right == 0:
            raise ZeroDivisionError("除数不能为零")
        if isinstance(node.op, ast.Pow):
            if abs(right) > _MAX_POW_EXPONENT:
                raise ValueError(f"指数过大（上限 {_MAX_POW_EXPONENT}），拒绝计算")
            if abs(left) > _MAX_POW_BASE:
                raise ValueError(f"底数过大（上限 {_MAX_POW_BASE}），拒绝计算")
        return op_func(left, right)                   # 真正计算

    if isinstance(node, ast.Call):
        if not isinstance(node.func, ast.Name):
            raise ValueError("只允许直接调用函数名，不支持链式调用")
        func_name = node.func.id
        if func_name not in _ALLOWED_FUNCTIONS:
            raise ValueError(f"不支持的函数: {func_name}")
        func = _ALLOWED_FUNCTIONS[func_name]
        args = [_safe_eval(a, depth + 1) for a in node.args]
        return func(*args)                            # 展开参数调用

    raise ValueError(f"未知节点类型: {type(node).__name__}")
```

#### handler 与工具定义

```python
def calculator_handler(expression: str) -> str:
    """计算器 handler."""
    if not expression or not expression.strip():
        raise ValueError("表达式不能为空")

    expr = expression.strip()
    try:
        tree = ast.parse(expr, mode="eval")          # mode="eval" 只解析表达式
    except (SyntaxError, ValueError, MemoryError) as e:
        raise ValueError(f"表达式无法解析: {e}") from e

    try:
        result = _safe_eval(tree)
    except RecursionError as e:
        raise ValueError("表达式过于复杂（递归过深），请拆分成更小的计算") from e

    if isinstance(result, float):
        if result == int(result):
            return f"计算结果: {int(result)}"         # 12.0 → 12
        return f"计算结果: {result:.6g}"              # 保留 6 位有效数字
    return f"计算结果: {result}"

        "properties": {
            "expression": {
                "type": "string",
                "description": "要计算的数学表达式，如 '25 * 4 + 10'、'sqrt(16)'",

        },

```

### 3.9 tools/todo_list.py —— 待办事项

**作用**：演示「有状态工具」，并且不同 session 的待办互相隔离。

```python
import threading
from . import Tool, CURRENT_SESSION_ID

# 全局状态：{session_id: [ {"id":1, "item":"买牛奶", "done":False} ]}
_state: dict[str, list[dict[str, Any]]] = {}
_lock = threading.Lock()          # 互斥锁，防止多线程同时改状态


def _ensure_session(session_id: str) -> list[dict[str, Any]]:
    with _lock:                   # 加锁
        if session_id not in _state:
            _state[session_id] = []      # 新会话给一个空列表
        return _state[session_id]


def _todos_to_text(todos) -> str:
    if not todos:
        return "(空)"
    lines = []
    for t in todos:
        marker = "✅" if t["done"] else "⬜"
        lines.append(f"  [{t['id']}] {marker} {t['item']}")
    return "\n".join(lines)


def todo_handler(action: str, item: str | None = None, session_id: str | None = None) -> str:
    # 优先级：显式传入 > 运行时注入 > 兜底全局
    effective_session = session_id or CURRENT_SESSION_ID.get() or "_global"
    todos = _ensure_session(effective_session)

    if action == "list":                                  # 查看
        return f"📋 当前待办:\n{_todos_to_text(todos)}"

    if action == "add":                                   # 添加
        if not item:
            raise ValueError("add 操作需要提供 item 参数")
        with _lock:
            new_id = max((t["id"] for t in todos), default=0) + 1
            # max(..., default=0)：空列表时也不会报错
            todos.append({"id": new_id, "item": item.strip(), "done": False})
        return f"✅ 已添加: {item.strip()}\n📋 当前待办:\n{_todos_to_text(todos)}"

    if action == "complete":                              # 完成
        if not item:
            raise ValueError("complete 操作需要提供 item 参数（ID 或关键词）")
        with _lock:
            target_id = int(item) if str(item).isdigit() else None
            found = None
            for t in todos:
                if target_id is not None and t["id"] == target_id:
                    found = t
                    break
                if item.lower() in t["item"].lower():     # 关键词模糊匹配
                    found = t
                    break
            if not found:
                return f"❌ 未找到匹配的待办: {item}\n📋 当前待办:\n{_todos_to_text(todos)}"
            found["done"] = True
        return f"🎉 已完成 [{found['id']}]: {found['item']}\n📋 当前待办:\n{_todos_to_text(todos)}"

    if action == "remove":                                # 删除
        if not item:
            raise ValueError("remove 操作需要提供 item 参数（ID 或关键词）")
        with _lock:
            target_id = int(item) if str(item).isdigit() else None
            removed = None
            for i, t in enumerate(todos):
                if target_id is not None and t["id"] == target_id:
                    removed = todos.pop(i)                # pop(i) 删除并返回
                    break
                if item.lower() in t["item"].lower():
                    removed = todos.pop(i)
                    break
            if not removed:
                return f"❌ 未找到匹配的待办: {item}"
        return f"🗑️ 已删除 [{removed['id']}]: {removed['item']}\n📋 当前待办:\n{_todos_to_text(todos)}"

    raise ValueError(f"未知操作: {action}（支持: add, remove, list, complete）")


TODO_TOOL = Tool(
    name="todo_list",
    description="待办事项管理工具，支持添加(add)、删除(remove)、列出(list)、标记完成(complete)。",
    parameters={
        "type": "object",
        "properties": {
            "action": {
                "type": "string",
                "enum": ["add", "remove", "list", "complete"],   # 只允许这四个值
                "description": "要执行的操作类型",
            },
            "item": {
                "type": "string",
                "description": "待办内容（add）或 ID/关键词（remove/complete）",
            },
        },
        "required": ["action"],          # item 不是永远必填，所以只要求 action
    },
    handler=todo_handler,
)
```

**这一节的核心**

- 工具可以有状态，状态存在模块级字典 `_state` 里。
- 用 `CURRENT_SESSION_ID` 区分会话，实现「窗口 1 的待办不会出现在窗口 2」。
- `_lock` 是线程锁：虽然 CLI 是单线程，但加锁是更稳妥的写法。

### 3.10 agent.py —— 核心 ReAct 循环（最重要）

**作用**：把前面所有零件组装起来：收消息 → 建上下文 → 调模型 → 解析 → 调工具 → 再循环，直到拿到最终答案。

#### 依赖与系统提示词

```python
"""
Agent — 核心 ReAct 循环.
Step 1: 接收用户输入
Step 2: 判断是直接回复还是调用工具（LLM 决策）
Step 3: 调用工具（如果需要）
Step 4: 根据工具结果判断继续 loop 还是返回
"""

from __future__ import annotations

import logging
import time
from typing import Any

from .exceptions import AgentError, ToolExecutionError, ToolNotFoundError
from .llm_client import LLMClient
from .memory import ContextManager
from .parser import ParsedResponse, parse_llm_response
from .sessions import SessionManager
from .tools import ToolRegistry

logger = logging.getLogger(__name__)


SYSTEM_PROMPT_TEMPLATE = """你是一个智能 Agent，可以理解用户问题并自主决定是否使用工具。

## 可用工具
{tools_description}

## 输出格式（严格遵守，只输出 JSON）
你必须且只能输出一个 JSON 对象，格式如下:
```json
{{
  "thought": "你的思考过程",
  "action": "tool_call" 或 "final_answer",
  "tool_name": "工具名称（仅当 action=tool_call 时必填）",
  "tool_args": {{"key": "value"}},
  "answer": "最终回答文本（仅当 action=final_answer 时必填）"
}}
```

## 决策规则
1. 如果用户问题可以直接回答 → action="final_answer"
2. 如果需要查信息、搜索、计算、操作待办 → action="tool_call"
3. 工具执行完后，根据结果给出 final_answer（不要再次调用相同工具）

```

**为什么 JSON 里要写 `{{` 和 `}}`？**
这个字符串后面会调用 `.format(tools_description=...)`。在 Python 的 `format` 语法里，`{` 和 `}` 是占位符，想输出真正的花括号必须写两遍。所以 `{{` 最终会变成 `{`。

#### Agent 构造函数

```python
class Agent:
    """最小可用 Agent."""

    def __init__(self, llm, tools, session_manager=None,
                 context_manager=None, max_steps=10, system_prompt_template=None):
        self.llm = llm
        self.tools = tools
        self.session_manager = session_manager or SessionManager()   # 没传就新建
        self.context_manager = context_manager or ContextManager()
        self.max_steps = max_steps                                   # 最多循环几轮
        self.system_prompt_template = system_prompt_template or SYSTEM_PROMPT_TEMPLATE
```

#### chat()：整个循环

```python
    def chat(self, session_id: str, user_input: str) -> str:
        """与 Agent 对话，返回最终回答."""
        session = self.session_manager.get_or_create(session_id)   # 找/建会话

        # Step 1: 记录用户输入
        session.add_message({"role": "user", "content": user_input})
        session.add_trace(f"👤 用户输入: {user_input}")

        # 把工具说明填进系统提示词
        system_prompt = self.system_prompt_template.format(
            tools_description=self.tools.get_tools_description_text()
        )

        start_time = time.time()                      # 记录开始时间，用于统计耗时

        for step in range(self.max_steps):            # 最多循环 max_steps 次
            step_num = step + 1                       # 人类习惯从 1 开始
            session.add_trace(f"\n{'='*50}")          # '='*50 生成 50 个等号
            session.add_trace(f"📦 Step {step_num}/{self.max_steps}")

            # Step 2: 构建上下文 + 调模型
            context = self.context_manager.build_context(
                session.get_messages(),
                system_prompt=None,       # system 单独传给 llm.chat
            )
            session.add_trace(
                f"📏 Context 大小: {len(context)} 条消息, "
                f"估算 {self.context_manager._estimate_chars(context)} 字符"
            )
            # 注意：这里调用了 ContextManager 的“私有方法”（下划线开头），
            # 只是为了打日志；严格来说可以在 ContextManager 里暴露一个公开统计方法。

            try:
                llm_response = self.llm.chat(
                    messages=context,
                    tools=self.tools.get_all_tools_schema(),   # 工具清单
                    system_prompt=system_prompt,
                )
            except Exception as e:
                error_msg = f"❌ LLM 调用失败: {e}"
                session.add_trace(error_msg)
                session.add_message({"role": "assistant", "content": error_msg})
                return error_msg          # 调模型失败，本轮直接结束

            # 解析模型输出
            parsed = parse_llm_response(llm_response.content)

            if parsed.thought:
                session.add_trace(f"💭 Thought: {parsed.thought}")   # 只进 trace

            session.add_trace(
                f"🎯 决策: action={parsed.action}, tool={parsed.tool_name or '-'}"
            )

            # Step 4: 分支
            if parsed.action == "final_answer":
                answer = parsed.final_answer or "(模型未给出答案)"
                session.add_message({"role": "assistant", "content": answer})
                session.add_trace(f"✅ Final Answer: {answer}")
                elapsed = time.time() - start_time
                session.add_trace(f"⏱️ 耗时: {elapsed:.1f}s, 共 {step_num} 步")
                return answer             # 结束整个 chat()

            if parsed.action == "tool_call":
                tool_name = parsed.tool_name or ""
                tool_args = parsed.tool_args or {}

                # 先把「我要调工具」写进会话，content 故意为空
                session.add_message({
                    "role": "assistant",
                    "content": "",
                    "tool_calls": [{
                        "name": tool_name,
                        "arguments": tool_args,
                        "id": f"call_{session_id}_{step}",    # 调用 ID
                    }],
                })

                # Step 3: 执行工具
                try:
                    tool_result = self.tools.execute(tool_name, tool_args, session_id=session_id)
                except ToolNotFoundError as e:
                    tool_result = f"❌ {e}"
                except ToolExecutionError as e:
                    tool_result = f"❌ {e}"
                except Exception as e:
                    tool_result = f"❌ 未知错误: {e}"
                # 工具失败也转成字符串继续，让模型有机会看到错误并调整

                tool_result_display = tool_result[:300] + ("..." if len(tool_result) > 300 else "")
                session.add_trace(
                    f"🔧 Tool call: {tool_name}({tool_args}) → {tool_result_display}"
                )

                # 工具结果写回会话，下一轮会自动进入 context
                session.add_message({
                    "role": "tool",
                    "tool_call_id": f"call_{session_id}_{step}",   # 必须和上面的 ID 一致
                    "content": tool_result,
                })

                continue    # 继续下一轮 for 循环（回到 Step 2）

            # 理论上 parser 已经兜底，这里只是最后保险
            fallback = f"⚠️ 无法解析 LLM 决策，原始输出: {llm_response.content[:500]}"
            session.add_message({"role": "assistant", "content": fallback})
            session.add_trace(fallback)
            return fallback

        # 循环次数用完了
        elapsed = time.time() - start_time
        overflow_msg = (
            f"⚠️ 达到最大步数限制 ({self.max_steps} 步)，Agent 未在限制内完成。\n"
            f"已进行的步骤可以在 trace 中查看。"
        )
        session.add_trace(f"⏱️ 超时: {elapsed:.1f}s, {self.max_steps} 步耗尽")
        return overflow_msg
```

#### 三个辅助方法

```python
    def get_trace(self, session_id: str) -> str:        # 取执行日志
        session = self.session_manager.get(session_id)
        if not session:
            return f"Session '{session_id}' 不存在"
        return session.get_trace_text()

    def get_sessions(self) -> list[dict[str, Any]]:     # 取所有会话概览
        return self.session_manager.session_info()

    def reset_session(self, session_id: str) -> bool:   # 清空一个会话
        session = self.session_manager.get(session_id)
        if session:
            session.reset()
            return True
        return False
```

**这一节的核心（必背）**

1. `for step in range(max_steps)` 就是 ReAct 循环。
2. 每轮都把「完整历史上下文 + 工具清单」发给模型。
3. 模型说 `final_answer` → 返回答案，结束。
4. 模型说 `tool_call` → 执行工具 → 把结果写回消息列表 → `continue` 再问模型。
5. `thought` 只写进 trace，不写进消息列表，避免污染上下文。
6. 工具调用的 `assistant.tool_calls[].id` 和 `tool.tool_call_id` 必须一致，否则真实 API 会报错。

#### 主循环

```python
def main() -> None:
    setup_console_encoding()
    setup_logging()

    api_key = os.environ.get("LLM_API_KEY", "")
    if not api_key or api_key.startswith("sk-your"):
        print("⚠️  未检测到有效的 LLM_API_KEY！")
        print("   请复制 .env.example 为 .env 并填入真实 API Key。")
        print("   程序仍会启动，但调用 LLM 时会失败。\n")

    print("🤖 Minimal Agent — 从零实现的最小可用 Agent")
    print("=" * 50)

    agent = build_agent()
    current_session = "default"

    print(f"✅ 已注册工具: {agent.tools.list_tools()}")
    print(f"🆔 当前 session: {current_session}")
    print_help()

    while True:                                   # 无限循环，直到用户退出
        try:
            prompt = f"[{current_session}] > "
            user_input = input(prompt).strip()    # 阻塞等待键盘输入
        except (EOFError, KeyboardInterrupt):     # Ctrl+D / Ctrl+C
            print("\n👋 再见！")
            break

        if not user_input:
            continue                              # 空输入直接下一轮

        if user_input.startswith("/"):            # 以 / 开头的是命令
            cmd = user_input[1:].lower()          # 去掉 /，转小写
            parts = cmd.split(maxsplit=1)         # 最多切一刀：命令 + 参数
            cmd_name = parts[0]
            cmd_arg = parts[1] if len(parts) > 1 else ""

            if cmd_name in ("quit", "exit", "q"):
                print("👋 再见！")
                break

            elif cmd_name == "help":
                print_help()

            elif cmd_name == "session":
                sid = cmd_arg.strip() or "default"
                current_session = sid
                agent.session_manager.get_or_create(sid)
                print(f"✅ 切换到 session: {sid}")

            elif cmd_name == "sessions":
                info = agent.get_sessions()
                if not info:
                    print("(暂无 session)")
                else:
                    # :<20 左对齐占 20 格，:>6 右对齐占 6 格
                    print(f"{'ID':<20} {'消息':>6} {'轮次':>6} {'最后更新':>20}")
                    print("-" * 54)
                    for s in info:
                        print(f"{s['id']:<20} {s['messages']:>6} {s['turns']:>6} {s['updated']:>20}")

            elif cmd_name == "trace":
                trace_text = agent.get_trace(current_session)
                print(f"─── trace for [{current_session}] ───")
                print(trace_text if trace_text else "(暂无 trace)")
                print("─── end trace ───")

            elif cmd_name == "reset":
                agent.reset_session(current_session)
                print(f"🔄 已重置 session: {current_session}")

            elif cmd_name == "tools":
                print("当前可用工具:")
                for name in agent.tools.list_tools():
                    print(f"  • {name}")

            else:
                print(f"❓ 未知命令: /{cmd_name}（输入 /help 查看帮助）")

            continue                              # 命令处理完，回到等待输入

        # 正常对话
        print("🤔 thinking...", end="", flush=True)   # 不换行，立即刷新
        try:
            answer = agent.chat(current_session, user_input)
        except Exception as e:
            print(f"\n❌ 运行异常: {e}")
            logging.exception("Agent chat 出错")      # 打印完整堆栈
            continue

        # 用回车 + 空格把 "thinking..." 擦掉，再打印答案
        print("\r" + " " * 14 + "\r", end="", flush=True)
        print(f"🤖: {answer}")
        print()


if __name__ == "__main__":     # 只有直接运行 python main.py 时才执行
    main()                     # 被 import 时不会自动跑
```

**这一节的核心**

- `while True + input()` 是命令行程序的标准骨架。
- 以 `/` 开头的是控制命令，其他都是发给 Agent 的问题。
- `__name__ == "__main__"` 保证模块被导入时不会执行主程序。

## 4. 把整个流程串起来：你问一句话，发生了什么

以「帮我算一下 25 * 4 + 10」为例：

### 第 1 轮

1. `main.py` 的 `input()` 读到这句话。
2. 调 `Agent.chat("default", "帮我算一下 25 * 4 + 10")`。
3. `SessionManager.get_or_create("default")` 拿到会话。
4. `session.messages` 变成：

```python
[
  {"role": "user", "content": "帮我算一下 25 * 4 + 10"}
]
```

5. `ContextManager.build_context` 清洗消息，`Agent` 再拼上 system prompt 和工具清单。
6. `LLMClient.chat` 发 HTTP 请求到大模型。
7. 模型返回（示意）：

```json
{
  "thought": "这是数学计算，应该用 calculator 工具",
  "action": "tool_call",
  "tool_name": "calculator",
  "tool_args": {"expression": "25 * 4 + 10"},
  "answer": null
}
```

8. `parse_llm_response` 解析成 `ParsedResponse(action="tool_call")`。
9. `Agent` 往 messages 追加一条 assistant 工具调用记录，再执行工具：

```python
ToolRegistry.execute("calculator", {"expression": "25 * 4 + 10"}, "default")
→ calculator_handler → _safe_eval → 110
→ "计算结果: 110"
```

10. 往 messages 追加 tool 结果：

```python
{"role": "tool", "tool_call_id": "call_default_0", "content": "计算结果: 110"}
```

11. `continue`，进入第 2 轮。

### 第 2 轮

12. 这时 messages 已经有 user + assistant(tool_call) + tool(result)。
13. 再次请求模型。模型这次返回：

```json
{
  "thought": "工具已经给出结果",
  "action": "final_answer",
  "tool_name": null,
  "tool_args": null,
  "answer": "25 * 4 + 10 = 110"
}
```

14. `Agent` 把回答写进 messages，并 `return "25 * 4 + 10 = 110"`。
15. `main.py` 打印 `🤖: 25 * 4 + 10 = 110`。

### 数据在哪些结构里

| 数据 | 存在哪 | 是否发给模型 |
| --- | --- | --- |
| 用户消息 | `session.messages` | 是 |
| 最终回答 | `session.messages` | 是 |
| 工具调用记录 | `session.messages` | 是 |
| 工具结果 | `session.messages` | 是（超 500 字截断） |
| 思考过程 thought | `session.trace` | 否 |
| 调试日志 | `session.trace` | 否 |

## 6. 常见疑问 FAQ

**Q1：为什么不用 OpenAI SDK，要手写 HTTP？**
题目要求不依赖 Agent 框架，手写 HTTP 更能体现「知道协议长什么样」。本质上 SDK 也是发这些字段。

**Q2：`LLMResponse` 和 `ParsedResponse` 有什么区别？**
`LLMResponse` 是「网络层结果」，`content` 是一段文本；`ParsedResponse` 是「业务层结果」，已经把文本翻译成 `action / tool_name / tool_args`。

**Q3：为什么既传 `tools` 参数，又在提示词里写工具说明？**
`tools` 是标准 function calling 协议；提示词里的说明是兜底，兼容不支持 `tools` 的模型。两边一起用，模型更容易理解。

**Q4：为什么 `thought` 不放进 messages？**
思考过程对下一轮决策帮助不大，反而占 token、干扰模型。把它留在 `trace` 里给人看就够了。

**Q5：为什么工具结果要截断到 500 字？**
搜索结果可能很长，全塞进上下文会让 token 爆炸、变慢、变贵。截断后仍保留关键信息。

**Q6：`max_steps=10` 用完了会怎样？**
返回一条「达到最大步数」的提示，不会死循环。这是防止模型反复调工具的安全阀。

**Q7：不同 session 为什么能隔离？**
消息存在 `Session.messages`，按 `session_id` 分开；待办工具通过 `CURRENT_SESSION_ID` 拿到当前会话，状态也按 id 分开。

**Q8：模型返回的不是 JSON 怎么办？**
`parser.py` 会依次尝试直接解析、代码块提取、大括号提取，最后实在不行就把整段文本当最终答案，程序不会崩。

**Q9：想加一个新工具要改哪几个文件？**
写一个 handler 函数 → 在 `src/tools/` 下新建文件用 `Tool(...)` 定义 → 在 `main.py` 的 `build_agent()` 里 `registry.register(你的工具)`。Agent 循环不用改。

**Q10：Windows 上中文/emoji 报错？**
`main.py` 的 `setup_console_encoding()` 已经处理：无法编码的字符替换成 `?`，不会中断程序。

## 附：一页纸速查

```
用户输入
  → main.py: input()
  → Agent.chat(session_id, text)
      → SessionManager.get_or_create
      → session.add_message(user)
      → for step in range(10):
          → ContextManager.build_context(messages)     过滤/截断/压缩
          → LLMClient.chat(context, tools, system)      POST /chat/completions
          → parse_llm_response(content)                JSON → ParsedResponse
          → if final_answer: 返回
          → if tool_call:
              → ToolRegistry.execute(name, args, session_id)
              → session.add_message(tool result)
              → continue
      → 达到 10 步：返回限制提示
  → 打印答案
```

看懂这条链路，就看懂了这个项目 80% 的代码。
